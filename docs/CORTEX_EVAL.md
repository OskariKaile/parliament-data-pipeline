# Cortex evaluation: can the AI reproduce Parliament's own topic tags?

Run on 9 Nov 2026 with [`snowflake/04_cortex_eval.sql`](../snowflake/04_cortex_eval.sql) (generated by [`tools/gen_eval_sql.py`](../tools/gen_eval_sql.py)), on a Snowflake trial account in AWS eu-north-1, with cross-region inference limited to `AWS_EU`.

## Why this test

Parliament Services tag every item with one or more of 28 official topics (Health, Energy, Migration, …). That is a free, human-made answer key. Before the enrichment step tags thousands of items, this checks how close Cortex gets to those tags and what each setup costs.

## Setup

- **Sample:** 300 items that have official topics and at least 200 characters of text. Picked by `ORDER BY HASH(BUSINESS_ID)`, so every variant sees exactly the same items. They have 2.43 official topics on average.
- **Input:** German title + the first 1,500 characters of the text.
- **Variants:**

| Variant | What it is |
|---|---|
| v0_majority_baseline | No AI: always predict the 2 most common topics |
| v1_classify_labels | `AI_CLASSIFY`, multi-label, the 28 topic names only |
| v2_classify_described | v1 + a 25-word description per topic |
| v3_classify_task | v2 + a task description ("Swiss parliamentary item, usually two or three topics") |
| v4_complete_json | `AI_COMPLETE` (llama3.1-70b) with a JSON schema whose `enum` is the 28 topics |

- **Metrics:** micro precision, recall and F1 over (item, topic) pairs; exact-set match (all topics right, nothing extra); topics predicted per item. A failed call counts as no prediction, so its official topics count as misses.
- **Cost:** credits and tokens per query from `SNOWFLAKE.ACCOUNT_USAGE.CORTEX_AI_FUNCTIONS_USAGE_HISTORY`. Usage showed up there within about 10 minutes.

## What I learned

1. **The AI is far better than guessing, but it is not a copy of the official tags.** F1 0.58–0.65 against 0.18 for the baseline, but only 6–16% of items get exactly the official set.
2. **Label descriptions were the biggest lever for `AI_CLASSIFY`.** With names only it assigns too many topics (3.05 per item against 2.43), so precision is 0.525. Short descriptions raise precision to 0.618. The task description adds a little more (F1 0.625 → 0.637) and brings the count down to 2.37.
3. **The general model with a JSON schema won on both quality and cost.** v4 had the best F1 at about 1/12 of v3's credits per item. `AI_CLASSIFY` was billed at about 1.6 credits per million tokens, and the descriptions add roughly 1,000 tokens to every call. llama3.1-70b was billed at about 0.43 credits per million tokens.
4. **But v4 failed on 5 of 300 items (1.7%):** the call returned NULL. The same items answered normally without the schema, so the structured-output step is what fails, not the model. The enrichment procedure therefore runs v4 first and uses `AI_CLASSIFY` (v3 setup) only for the rows that came back NULL. That is a separate `UPDATE`, so `AI_CLASSIFY` is never evaluated for the other rows.
5. **Concrete topics are easy; broad ones are where it goes wrong.**

| Topic | Official | v3 predicted | v3 F1 | v4 predicted | v4 F1 |
|---|---|---|---|---|---|
| Energy | 14 | 14 | 0.929 | 15 | 0.897 |
| Health | 66 | 64 | 0.908 | 65 | 0.901 |
| Migration | 27 | 26 | 0.830 | 29 | 0.857 |
| Environment | 56 | 46 | 0.824 | 50 | 0.830 |
| Government and politics | 44 | 105 | 0.376 | 94 | 0.391 |
| Public finance | 49 | 16 | 0.338 | 40 | 0.494 |
| Social issues | 37 | 8 | 0.311 | 22 | 0.576 |
| Human rights | 13 | 35 | 0.208 | 26 | 0.205 |
| Law (general) | 7 | 31 | 0.105 | 51 | 0.207 |

Both setups over-assign the catch-all topics (*Government and politics*, *Law (general)*, *Human rights*). `AI_CLASSIFY` under-assigns *Public finance* and *Social issues*, where v4 is clearly better. Some of this "error" is defensible: the broad topics overlap by design, and the official tags are a human judgement too.

6. **Model choice depends on the region.** llama3.3-70b, the model I planned to use, is not offered through `AWS_EU` cross-region inference. I tested which models answer from this account: llama3.1-70b, llama3.1-8b, mistral-7b, claude-sonnet-4-5 and claude-haiku-4-5 work; mistral-large2, llama4-maverick, openai-gpt-4.1 and snowflake-llama-3.3-70b do not. I chose llama3.1-70b so the data stays in the EU, rather than opening inference to `ANY_REGION`.

## What changed because of this

- `AI.ENRICH` ([03_cortex_enrichment.sql](../snowflake/03_cortex_enrichment.sql)) tags topics with the v4 prompt and schema, and falls back to `AI_CLASSIFY` for NULL rows.
- A 100-item pilot of the full enrichment (English title, summary, topics, AI/digital flag) used 0.086 AI credits, about 0.86 credits per 1,000 items. `AI_FILTER` was the largest part of it.

## Full backfill (9 Nov 2026)

`AI.ENRICH` ran over all 6,690 items in chunks of 1,000 (so one failure cannot lose the whole run), in 27 minutes on an XSMALL warehouse.

| | |
|---|---|
| Items enriched | 6,690 of 6,690; no missing title, summary, topics or flag |
| Flagged as AI / data / digital | 573 (8.6%) |
| Topics from the fallback (`AI_CLASSIFY`) | 405 items (6.1%), more than the 1.7% in the evaluation, which only used items with at least 200 characters of text |
| AI credits for the backfill | about 6.5 (the day's total incl. evaluation and tests: 8.15) |

AI credits for the whole day by function: `AI_FILTER` 3.49, `AI_COMPLETE` 2.18, `AI_CLASSIFY` 2.03 (mostly the evaluation), `AI_TRANSLATE` 0.44. The yes/no `AI_FILTER` was the most expensive step, so it is the first place to save: for example, run it only on the title plus the first 500 characters.

**One real problem found by reading the output.** 234 items have only a title and no text (elections, extraordinary sessions, new petitions). Their summaries added details that are not in the source. One said the Federal Council was summoned to an extraordinary session, but the session is Parliament's. I removed those 234 summaries, and the procedure now writes no summary when there is no text. The English title still covers them.

## What I would try next

- Rewrite the descriptions of the five weakest topics and re-run. With v4 that costs about 0.05 credits.
- Run v4 with claude-haiku-4-5 (available in the EU) to compare quality per credit.
- Retry NULL rows once without the schema before falling back to `AI_CLASSIFY`.
